# StudyBuddy project audit — 2026-09-07

## Scope and method

This is a local, source-only audit. No source code, credentials, or user data were sent to an external audit service. `command -v ponytail` returned no executable and a repository search found no Ponytail reference, so a vendor/tool-specific Ponytail audit could not be run. The review instead applied the practical Ponytail principles requested: smallest reversible changes, reuse installed platform APIs, avoid unnecessary dependencies, retain explicit upgrade paths, and document unresolved risk.

The working tree already contained substantial uncommitted Capacitor/offline/focus work before this audit. No commit, push, deploy, database migration, production configuration change, or destructive Git action was performed.

## Verified changes

### Offline integrity and privacy — remediated

- The durable outbox uses stable mutation IDs, strict FIFO replay, persisted attempts/errors, temporary Todo-ID reconciliation, retained `409` conflicts, and idempotent `404` Todo deletes. Regression coverage is in `tests/frontend/offline-outbox.test.ts`.
- Todo update/delete first requests now also carry stable client mutation IDs, and retryable `5xx` failures are eligible for durable replay without queuing auth, validation, or conflict failures.
- `APIResponseError` prevents a cached GET snapshot from being returned after an HTTP rejection even when the browser reports offline.
- Logout clears account snapshots, queued writes, focus/device markers, tab drafts, React Query state, and StudyBuddy cache. A remembered signed-in account marker gates offline `/auth/me` bootstrap; an online account switch clears the old account cache before persisting the new profile.
- `public/sw.js` now caches only public static assets. It deliberately excludes API responses, navigation/document HTML, `Set-Cookie`, `private`, and `no-store` responses. Failed navigation gets only the unauthenticated offline fallback.
- The privacy policy now discloses signed-in offline storage and the optional Android focus guard.

### Android reminders and focus enforcement — remediated with explicit consent

- Android preparation is repeatable through `scripts/prepare-android.mjs`; it adds the exact-alarm permission, status icon, foreground-service declaration, Android backup opt-out, tracked Java sources, and plugin registration after every Capacitor sync.
- Settings renders Android-only exact-alarm controls and an explicit Usage Access/overlay disclosure for the phone-wide focus guard.
- `FocusEnforcerService` only runs after opt-in, checks the current foreground package while a remote StudyBuddy focus session is active, ignores StudyBuddy, displays an overlay with an **Open StudyBuddy timer** action, and ends the StudyBuddy session after 150 seconds of continued external use.
- The native bridge is pinned to `https://sbd.satym.in/api`; it does not accept an arbitrary HTTPS host before attaching WebView cookies. Generated Android builds set `android:allowBackup="false"`.
- The service does not use Accessibility, record app history, lock the phone, or force-stop apps.

### Performance, analytics, and focus consistency — improved

- Timer analytics now records `completedAt` for new Todo completions and uses it for analytics, with a due-date fallback only for legacy documents.
- `RescheduleAllOverdue` now executes an indexed MongoDB update instead of loading every incomplete Todo into memory.
- Leaderboard queries use a MongoDB field projection and a public rate limit.
- `focus_sessions` now declares a partial unique active-session index, TTL retention index, and bounded contention retry. Existing production data must be deduplicated before the unique index can be guaranteed to build.
- `AnalyticsDashboard` normalizes input, presents a timezone-aware narrative, explains method/legacy caveats, exposes bar tooltips/accessible summaries, and avoids causal claims. `tests/frontend/analytics-insights.test.ts` covers core interpretation logic.
- The fullscreen timer retains `100dvh`, sticky controls, short-landscape two-column behavior, responsive clock clamps, and a source-level regression test at `tests/frontend/fullscreen-timer-responsive.test.ts`.

### Optional Redis realtime — no caching or PostgreSQL migration

- `REDIS_URL` enables optional Redis Streams long polling only. Events contain a topic and timestamp; clients refetch authenticated REST data. Without Redis, MongoDB and existing polling remain functional.
- Redis support is implemented in `backend/internal/realtime/` with the pinned `github.com/redis/go-redis/v9 v9.7.0` dependency. It is disabled by default and was not pointed at an external Redis server during this audit.
- PostgreSQL migration assets, importer, Compose topology, and `pgx` dependency were intentionally removed. MongoDB remains the sole active datastore.

## Dependency/security review

- Updated Next.js to exact `16.3.4`, then applied non-breaking `npm audit fix` updates. This removed the earlier Next/PostCSS, Browserslist, and nanoid findings.
- Final `npm audit --omit=dev --audit-level=high` still reports one `tar` dependency chain with one high and one critical advisory. It is inherited through Capacitor CLI 6; npm's only proposed fix is `npm audit fix --force`, which upgrades `@capacitor/cli` to `8.5.1` and requires a breaking Capacitor migration. It was intentionally not forced.
- npm warned that local allow-scripts policy blocked `esbuild` and `unrs-resolver` install scripts. The production build and APK build nonetheless passed; do not weaken that policy without independently reviewing those scripts.

## Open risks and release gates

1. **Remote Capacitor shell:** `server.url` still points to the deployed web app. First-ever offline launch cannot provide a full authenticated app; cached reads/writes work only after an online session has initialized local state.
2. **Physical device verification:** exact alarms, OEM battery behavior, Usage Access, overlay behavior, Android Play disclosures, and the 150-second phone-use flow need real-device/manual testing before release.
3. **Platform authority:** a normal Android app cannot lock the OS or kill/block other apps. Device-owner/MDM is required for genuine device control.
4. **Mongo focus index rollout:** clean any pre-existing duplicate active focus documents before relying on `uq_focus_user_active`; monitor index setup logs in a staging environment.
5. **Redis operational validation:** if Redis realtime is enabled, configure a staging `REDIS_URL`, load test long polling, confirm stream retention, and observe failover behavior before calling it production-ready.
6. **Reverse-proxy rate limiting:** confirm the production proxy trust model before setting Fiber's proxy header; blindly trusting `X-Forwarded-For` would permit spoofed client IPs.
7. **Dependency release blocker:** plan and test the Capacitor 6→8 migration to clear the remaining `tar` advisory. Do not use `npm audit fix --force` unattended.
